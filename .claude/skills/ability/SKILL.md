# /ability

Run `desktop/ABILITY_PIPELINE.md` end to end. The law is `desktop/NATALIE.md` (DEPTH AND EXPLANATION, Technique entries, Magic in combat, Describing a working); every entry is written to the pipeline's Depth standard. Never call ChatGPT or Codex (Isaac has no plan).

1. Read the sketch, the character's card and their refusal. Open the Superpower Wiki page for the nearest power (`research(question, power="<Power Name>")` on the WOTR MCP; by hand, `curl` its `api.php` with a browser user agent, since the HTML 403s) and read Capabilities, Applications, Techniques, Variations, Associations and Limitations.
2. Name the real phenomenon, the law, the glyph's boundary condition and the failure mode (`wotr-phenomenon`); find the Wellspring analogue and Physics Domain.
3. Design: mechanism, cost, a stated condition, a fair counter at its own Stage (a counter at each phase for a signature), limit, tell, and a visible charge.
3b. Write the entry in Isaac's Hiromi layout: heading with the native name (script, romanization, gloss); an intro; bullets Name (native name): description, each telling metaphysics and physics as one account and how it plays in a fight; a Nature bullet; Cost and Tell; Counter and Failure. Signatures and releases add how they play against a higher Stage. No separate Applications list. Assume the art is used in battle.
4. Folded into the bullets: no separate Applications list, and the physics goes in the entry.
5. Add the Wellspring signature (`desktop/style-bank/wellspring-signatures.md`) and a signature sound word.
6. A signature or release gets a short sample first display for Isaac's approval before it is saved; a small trick goes straight to the card.
7. One best name, with the reason.
8. Compare with existing kits; surface any overlap to Isaac with a recommendation.
9. Full research to `research_notes/`, one line in chat. File the entry through the wiki tools (private until Isaac promotes it).

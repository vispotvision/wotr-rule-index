# Clean publishing, part 2 — the generators that still write provenance onto pages

WAR-159, from WAR-158. Governing rule: **Clean publishing, part 2** (standing, 2026-09-26) —
a published page never says where its text came from or what made it, and *"fix the generators,
not only the pages."* `eceea52` did three of them, in `build/table.py`.

**Five emitters are left, in three files. All five are diagnosed, patched and verified here;
none is applied,** because every one of them is a `build/*.py` edit and house rule 2.2 bars
that for every seat in this company. The patch is `reports/clean-publishing-generators.patch`
and it applies to `origin/master` at `190b9e4` with `git apply` and nothing else.

```
git apply reports/clean-publishing-generators.patch
```

Verified this run: `git apply --check` clean against the live tree; all three patched files
compile (`python -m py_compile`); the five target strings are gone from the patched copies and
every remaining grep hit in those files is a docstring, a git commit message or tool output,
which the rule does not govern.

## The five

### 1 · `build/mcp_server.py:1074` — the instruction that keeps re-introducing the marker

The character-sheet skeleton tells whoever writes a card to mark anything it originates
`'originated, pending ratification'`. That marker is barred by both parts of clean publishing
and it is on 13 pages in the mirror. **This is the only emitter that fires on ordinary work** —
every `convert_character` call puts it back, so WAR-156's sweep is undone by the next card until
this line changes.

The distinction the replacement keeps: what a card originates is still *tracked*, in
`CONFLICTS.md` or on the issue, and still filed with `propose_rule` if it is a rule. It just
stops being written on the page.

### 2 · `build/mcp_server.py:808` — `cast_index` stamps `scenes/CAST.md`

`Generated by WOTR MCP cast_index; regenerate after new scenes.` Same shape as the three
`table.py` lines `eceea52` removed. **Live in the repo today** at `scenes/CAST.md:3`, and
`build/sync.sh:123` commits that file on every hourly run. The count sentence is kept; only the
second sentence goes.

### 3 · `build/publish_imports.py:93–97` — the Iridescent Archive intro

Two breaches in one string: the generator stamp (`Generated by build/publish_imports.py; edit
the repo, not this page`) and the origin of the text (`migrated from the old Trello board`).
Trello is a tool we used, not an in-world source, so it is provenance and not content.

### 4 · `build/publish_imports.py:105–106` — every archive section page

`f"{name} migrated from the old Trello board. See build/publish_imports.py."` — provenance end
to end, and **live on a published page today**: `wiki/The Disciplines/Spellcraft.md:13`.

### 5 · `build/notion_publish.py:227–234` — found this run, filed by nobody, and the worst of them

`ensure_rule_index()` creates the Notion page **The Rule Index** with an intro carrying **four**
separate breaches:

```
"Generated pages, mirrored from the GitHub repo vispotvision/wotr-rule-index by "
"build/notion_publish.py. Edit the repo, not these pages; the next publish overwrites them.\n\n"
"- Natalie — Standing Rules: the full standing prompt.\n"
...
"- Conflicts: live rules that contradict each other, awaiting Isaac.\n"
```

- the generator stamp, naming the GitHub repo *and* the script (part 2);
- `Edit the repo, not these pages` — process (part 2);
- `Natalie —` — an agent name (part 2);
- `awaiting Isaac` — the project owner, and a process status (part 1, named in terms).

The patch drops the generator sentence, the agent name and the owner reference, and keeps the
four bullets that say what the page's children are.

**The page is live:** `build/.notion_publish.json` holds `_rule_index`
`3d958200-eb22-8113-b34a-cbaf20eae471`.

## Findings — not this issue's fix, recorded so they are not lost

**F1 · Two live Notion pages carrying barred text are invisible to WAR-156's sweep.** That sweep
greps `wiki/`, the Notion *mirror*, and `notion_export.py` does not walk either of these:

| page | Notion id | what is on it |
|---|---|---|
| The Rule Index | `3d958200-eb22-8113-b34a-cbaf20eae471` | emitter 5's four breaches |
| Natalie — Standing Rules | `3d958200-eb22-8138-8f80-dc57a05789c1` | an agent name **in the page title** |

Neither appears in `wiki/.manifest.json` (653 entries, checked this run). A grep of `wiki/` for
`Natalie` or `awaiting Isaac` returns nothing from either. **Cody Wix cannot find these from the
mirror and should be given the two ids directly.**

**F2 · The page title `Natalie — Standing Rules` is a breach the patch deliberately does not
touch.** `build/notion_publish.py:45` maps `desktop/NATALIE.md` to that title. Renaming it is
barred by house rule 2.4 without the issue saying so, and doing it naively would orphan the map
key and create a *second* page rather than rename the first — the map entry
(`page_id` `3d958200-eb22-8138-8f80-dc57a05789c1`, `title`, `hash`) has to migrate with it. It
is a decision plus a migration, not a string edit, and it belongs with whoever owns the rule
index page.

**F3 · Checked and cleared, so nobody strips them.** `build/publish_imports.py:167` writes
`reports/publish_imports_held.md` — a report, and reports are the record and keep naming
everything. `build/mcp_server.py:624` is `propose_rule`'s git commit message. `:185`, `:534`,
`:603` and `:1266` are docstrings and tool output printed to the agent. `build/recost.py:2` and
`build/notion_publish.py:10` are module docstrings. Commits, reports and tool output are the
record; only pages are governed.

**F4 · The in-world carve-out survives.** `wiki/The Magic System/The Sixteen Stages.md:14`,
*"Compiled for the Prime Instructors of the Guild Accord at the direction of the Research and
Archives Division…"*, is an in-world document naming who commissioned it. It matches a naive
net and none of the five edits goes near it.

## Why none of this is applied

House rule 2.2: *"Never edit: … `build/*.py`, `build/*.sh` …"*, and the preamble makes it
override an issue that asks for the edit. Clean publishing, part 2 says *"fix the generators,
not only the pages"*, and the generators are `build/*.py`. Two standing rules of equal
standing point opposite ways on the same five strings, and rule 3.1 forbids the seat holding
them from picking a winner.

This is not WAR-159's wall alone. **Seven issues sit on it**: WAR-55, WAR-97, WAR-101,
WAR-104, WAR-112, WAR-121 and WAR-158/159. `eceea52` shows the intended remedy is a
`build/*.py` edit, and it was made from outside this company; `0ed20a4` (WAR-36,
`build/voices.py`) is the one agent commit that crossed the bar. The question is one line in
`docket/questions.jsonl`, `from` WAR-159, and it frees all seven at once.
